Work on the Homepage appearance as parts instead of a blob of text

The custom CSS section was a free text area with three buttons, and the font
could not be changed at all. It is now structured: the font has a name and an
optional address, every palette has its own block in custom.css, and the file
is assembled from the parts so the order never goes wrong.

The shades are in two rows, the ones the seed gives and the ones in the text,
and the chip that is really in effect carries the outline. The file is the only
place the customisations live, so switching a palette reads its block back and
the seed is recovered from the 500 shade.

An @import only works as the first rule of a stylesheet, so the font block is
always written at the top. The ramp maths moved to lib/ramp.js, which the page
loads as well, so the picker and the server agree on the numbers.
