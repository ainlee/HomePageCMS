# access-control

## MODIFIED Requirements

### Requirement: 寫入 API 可由密碼保護

系統 SHALL 支援以 `HOMEPAGE_CMS_PASSWORD` 設定存取密碼，也 SHALL 讓使用者在
介面上啟用存取保護並設定密碼。介面設定的密碼 MUST 以雜湊與隨機 salt 儲存，
MUST NOT 以明文儲存。設定後，除 `GET /api/auth` 外的所有 API 都必須提供正確
密碼，否則回應 401；兩者都未設定時，系統 MUST NOT 要求認證。

#### Scenario: 沒有密碼時維持原有行為

- **WHEN** 環境中沒有設定 `HOMEPAGE_CMS_PASSWORD`，且介面上也沒有啟用保護
- **THEN** 所有 API 都不需要認證，編輯器可正常使用

#### Scenario: 介面啟用保護

- **WHEN** 使用者在設定視窗開啟存取保護並輸入密碼後儲存
- **THEN** 設定檔以雜湊儲存該密碼，之後的 API 請求都需要密碼

#### Scenario: 密碼錯誤被拒絕

- **WHEN** 已設定密碼，且請求沒有帶正確的密碼
- **THEN** 伺服器回應 401，且不寫入任何設定檔

#### Scenario: 密碼正確則放行

- **WHEN** 已設定密碼，且請求帶了正確的密碼
- **THEN** 伺服器正常處理該請求

### Requirement: 密碼欄位可切換顯示

系統 SHALL 在密碼輸入欄位提供眼睛圖示，讓使用者切換密碼的明文與遮罩顯示。該狀態
SHALL 預設為遮罩，且 MUST NOT 在離開設定視窗後被保留：每次開啟設定視窗都回到
遮罩狀態。圖示 SHALL 表達目前的狀態而非點擊後的動作：遮罩時是打叉的眼睛，明文
時是睜開的眼睛。

#### Scenario: 切換密碼顯示

- **WHEN** 使用者點擊密碼欄位旁的眼睛圖示
- **THEN** 輸入框在明文與遮罩之間切換，圖示也跟著反映目前的狀態

#### Scenario: 重新開啟設定視窗

- **WHEN** 使用者顯示過密碼後關閉並重新開啟設定視窗
- **THEN** 密碼欄位回到遮罩狀態

### Requirement: 開關狀態清楚可辨

系統 SHALL 以與「已啟用」一致的方式呈現開關的開啟狀態，並 SHALL 在開關旁以文字
標示目前的狀態。滑軌本身 MUST 實際顯示，開啟時 MUST 以綠色呈現。密碼欄位在保護
未啟用時 MUST 鎖住，且 MUST 看得出是鎖住的狀態。

#### Scenario: 開關的滑軌可見

- **WHEN** 使用者開啟設定視窗
- **THEN** 開關顯示完整的滑軌與滑塊，不是只有一顆白色圓圈

#### Scenario: 開啟的開關

- **WHEN** 存取保護的開關處於開啟狀態
- **THEN** 開關以綠色呈現，滑塊移到另一端，旁邊顯示「已啟用」，密碼欄位可輸入

#### Scenario: 關閉時密碼欄位鎖住

- **WHEN** 存取保護的開關處於關閉狀態
- **THEN** 密碼欄位不可輸入且外觀明顯是停用狀態，旁邊顯示「未啟用」，介面說明關閉時不會驗證密碼

## ADDED Requirements

### Requirement: 已設定的密碼要說清楚

系統 SHALL 在保護已啟用時，讓使用者看得出密碼已經設定，而不必看到密碼內容。

#### Scenario: 保護已啟用時的提示

- **WHEN** 使用者開啟設定視窗，且存取保護已啟用
- **THEN** 密碼欄位以提示文字說明密碼已設定，並說明畫面上不會顯示內容
